3. HOW TO PREVENT ACCIDENTALLY UPLOADING .ENV.LOCAL TO GITHUB
--------------------------------------------------------------------------------

1. ENSURE .ENV.LOCAL IS LISTED IN .GITIGNORE:
   Verify that your root `.gitignore` file explicitly includes `.env*.local` and `.env`.
   Example snippet in `.gitignore`:
   ---------------------------------
   # local environment files
   .env
   .env*.local
   .env.development.local
   .env.test.local
   .env.production.local
   ---------------------------------

2. USE A `.ENV.EXAMPLE` TEMPLATE FOR COLLABORATORS:
   Create a safe `.env.example` file containing dummy values (no real secrets) 
   and commit that to Git so team members know which variables are required.

3. PREVENT CLIENT EXPOSURE BY OMITTING `NEXT_PUBLIC_`:
   Never prefix sensitive API keys (like `OPENAI_API_KEY` or `FIREBASE_ADMIN_PRIVATE_KEY`) 
   with `NEXT_PUBLIC_`. If a key starts with `NEXT_PUBLIC_`, Next.js bakes it directly 
   into the public client JavaScript bundle, making it visible to anyone inspecting DevTools.

4. USE ENVIRONMENT SECRET MANAGERS IN DEPLOYMENT:
   For production hosting (such as Vercel, Netlify, or AWS), inject secret variables 
   directly into the hosting provider's Dashboard Environment Settings or GitHub Actions 
   Secrets rather than hardcoding them in files.

5. SET UP PRE-COMMIT GIT HOOKS (GIT-SECRETS / TRUFFLEHOG):
   Use automated security tools like `git-secrets` or `trufflehog` to automatically scan 
   outgoing git commits and block any accidental pushes containing API keys or private RSA keys.
